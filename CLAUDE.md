# radio-app

Простое радио-приложение: список интернет-радиостанций и плеер.

## Стек

- **Expo SDK 58** (`expo` ^58), React Native 0.88, React 19.3. Переход с 57 сделан 16 ноября 2026 через `npx expo install expo@^58.0.0 --fix` с чистой переустановкой (`package-lock.json` и `node_modules` удалялись: старый lock не давал разрешить необязательную peer-зависимость `expo-symbols`, сам пакет не использовался и удалён). Особенности 58, которые уже учтены в коде: у своей панели вкладок в `tabBar` больше нет `navigation`, вместо него `emitter.emit({ type: "tabPress", … })` и `navigateToTab(route.key)`; на iOS 26 заголовки нативного стека по умолчанию прозрачные, поэтому в стеках городов и профиля стоит `headerTransparent: false`; `ListHeaderComponent` и цвет иконок `Ionicons` не принимают `null`. `react-native-gesture-handler` 3: старый builder-API (`Gesture.Pan()`, `Gesture.Race()`, …) работает, но помечен устаревшим, при следующей крупной правке жестов переводить на хуки `usePanGesture`/`useCompetingGestures`. Веб-сборка по-прежнему не используется (`web.output: static`).
- Тема только светлая: все цвета в коде заданы жёстко, поэтому в `app.json` стоит `userInterfaceStyle: "light"`. Без этого в тёмной теме системы iOS делает строку состояния белой, и на светлых экранах пропадают часы и батарея (замечено на iPad). Строка состояния по умолчанию тёмная; единственный экран с тёмным фоном, глобус, задаёт светлую опцией `statusBarStyle: "light"` нативного стека в своём `Stack.Screen`. Новому тёмному экрану делать так же. Почему именно так: в `ios.infoPlist` стоит `UIViewControllerBasedStatusBarAppearance: true` (Expo по умолчанию пишет `false`, а при `false` React Native 0.88 зовёт общий API `UIApplication`, который в приложениях, собранных iOS 27 SDK, ничего не делает, см. `RCTStatusBarManager.mm`). При `true` система спрашивает стиль по цепочке контроллеров `react-native-screens` до активного экрана (корневой контроллер Expo и `<StatusBar>` из JS до ответа не доходят), и стиль берётся из опции экрана, а без неё из `auto`, то есть тёмный в светлой теме. В Expo Go ключ выключен, и та же опция вызывает красный экран ошибки от `react-native-screens`, поэтому глобус ставит её только вне Expo Go (`IS_EXPO_GO` из `src/lib/expo-go.ts`), а в Expo Go рендерит `<StatusBar style="light" />` из `expo-status-bar`, пока экран в фокусе.
- **TypeScript** в строгом режиме (`"strict": true` в `tsconfig.json`). Никаких `any`, `// @ts-ignore` и неявных типов.
- **Expo Router** — файловая навигация. Экраны лежат только в `src/app/`, `_layout.tsx` описывает навигатор. Структура: корневой Stack (`index.tsx` — редирект с `/` на `/cities`) → группа `(tabs)` с пятью вкладками: Города (`cities/` — свой Stack: глобус, список и `[id]`), Поиск, Станции (`stations.tsx`, избранные станции, звезда), Треки (`tracks.tsx`, понравившиеся треки, сердце), Профиль (`profile/` — свой Stack: настройки и выбор языка). Панель вкладок своя (`(tabs)/_layout.tsx`), плеер `PlayerBar` рендерится внутри неё над кнопками. Пакет `@react-navigation/bottom-tabs` не ставить: expo-router 57 несёт свою копию, вторая ломает типы и контексты.
- Настройки пользователя (имя, язык, стартовая страница) — `src/providers/settings-provider.tsx`, избранные треки и плейлист станций — `src/providers/favorites-provider.tsx`; оба хранят JSON в `expo-sqlite/kv-store`.
- Остальной код (компоненты, хуки, данные, утилиты) — в `src/` вне `src/app/`. Алиас `@/*` указывает на `./src/*`.
- iPad и широкие экраны. `ios.supportsTablet` включён; `orientation` остаётся `portrait`, поэтому iPhone заперт в портрете, а для iPad Expo сам прописывает все четыре ориентации (без них App Store не принимает сборку с многооконностью; `requireFullScreen` не используем). Содержимое не растягивается шире `CONTENT_MAX_WIDTH` (720) из `src/lib/layout.ts`: стиль `layout.content` стоит в `contentContainerStyle` каждого списка, на строке карточки города, на содержимом плеера и на кнопках панели вкладок, а фон этих панелей остаётся во всю ширину. Новый экран со списком обязан добавить `layout.content` так же. Глобус ограничивать не нужно: вертикальный угол камеры фиксирован, шар занимает около трёх четвертей высоты области при любой ширине, а размер буфера и пропорции камеры пересчитываются при повороте (эффект по `width`/`height` в `earth-gl.tsx`). Веб-сборка не поддерживается и для проверки раскладки не годится: `expo-sqlite` на вебе требует wasm, которого нет в настройке Metro.
- Персонажи приложения — бобёр в кепке (`src/components/beaver.tsx`) и весёлый утконос в наушниках (`src/components/platypus.tsx`), оба с магнитофоном (`src/components/boombox.tsx`): нарисованы на `react-native-svg`, анимированы `react-native-reanimated` через общий скелет `useDanceRig`/`DanceNotes` из `src/components/dance-rig.tsx`. В плеере и профиле рендерится `Character` из `src/components/character.tsx`, который берёт выбор из настройки `character` (переключатель в профиле, по умолчанию бобёр). Утконос — собственный рисунок без федоры и других примет Перри из «Финеса и Ферба»: это персонаж Disney, копировать его нельзя. Громкость и тембр для танца считаются в `src/hooks/use-dance-energy.ts` из PCM-сэмплов `useAudioSampleListener`; без сэмплов бобёр танцует под свой ритм.
- Главный экран — трёхмерный глобус `src/components/earth-gl.tsx` на `expo-gl` + `three` (через `expo-three`: `Renderer`, `TextureLoader`): сфера с текстурой NASA Blue Marble (`assets/textures/earth-blue-marble-5400.jpg`, оригинал 5400×2700 без пересжатия, ~2,5 МБ, источник и лицензия в `assets/textures/README.md`; размер не степень двойки, для WebGL 2 это допустимо), освещение, свечение атмосферы шейдером, маркеры городов как InstancedMesh, нажатие через Raycaster по сфере → ближайший город. Жесты (вращение, щипок, нажатие) в `src/hooks/use-globe-gestures.ts` через `react-native-gesture-handler`; положение шара живёт в ref и применяется к сцене напрямую, React не перерисовывается; кадр запрашивается только когда сцена помечена dirty, постоянного цикла отрисовки нет. Версию `three` держать в пределах peer-зависимости `expo-three` (сейчас ^0.166). Рендерер создавать только через `createRenderer` из `src/lib/three-renderer.ts`: three r163+ бракует контекст expo-gl как WebGL 1 (ложно, из-за наследования классов-заглушек), хелпер обходит проверку. Текстуры в GPU грузить только через `loadTextureFromAsset` оттуда же (шестиаргументный `texImage2D` expo-gl без UNPACK_FLIP_Y, переворот UV-матрицей): стандартный загрузчик expo-three/three роняет приложение нативно. Текстовый список городов остался на экране `cities/list`. При каждом запуске, который начинается с глобуса (стартовая страница «глобус» или не найден сохранённый город), экран показывает вступление: шар появляется над Америкой и за пять секунд перелетает к цели (`flight` и `initialView` у `EarthGL`, анимация прерывается жестом и уходом в фон). При самом первом запуске вступление идёт независимо от стартовой страницы, цель — Амстердам, в конце включается Radio Boven IJ; признак `introSeen` хранится в настройках (пока не записан, первый запуск считается не состоявшимся). При следующих запусках цель — случайная избранная станция (в конце она включается), а без избранного — случайный город из Амстердама, Парижа, Лиссабона и Лондона без включения станции; цель выбирается один раз за запуск после чтения настроек и избранного (`ready` у обоих провайдеров). При выборе станции в поиске или избранном (`flyToStationAndPlay`) поток подключается сразу, параллельно перелёту. Запасной режим `CONNECT_AFTER_LANDING` в `globe-navigation.ts` (подключение после приземления через `play` с `delayMs`) выключен и оставлен до проверки на устройстве. Кнопка глобуса в заголовке остальных экранов (`src/components/globe-button.tsx`) и выбор станции в поиске или избранном (`flyToStationAndPlay` из `src/lib/globe-navigation.ts`) кладут запрос в `src/lib/globe-flight.ts` (`requestFlight` с точкой `GlobePoint`, читается через `useFlightRequest`) и зовут `navigate("/cities")`. Точка станции (`getStationPoint`) — её город, а у станции без города (страновые списки, снимки в избранном) — столица страны из `src/data/capitals.ts` (таблица для стран с полными списками, иначе крупнейший город страны на глобусе); при добавлении страны в `generate-countries` столицу нужно дописать туда же; экран глобуса сам запрашивает такой же перелёт при возврате приложения на экран (`useAppActive`), если за время блокировки или фона станцию сменили с экрана блокировки, наушников или CarPlay: шар летит от места, где стоял, к играющей станции; параметры маршрута для этого не используются, потому что навигация с параметрами кладёт в стек второй экземпляр глобуса.
- Воспроизведение аудио — `expo-audio`. Состояние плеера живёт в `src/providers/player-provider.tsx`, панель плеера рендерится в корневом `_layout.tsx` под навигатором. На каждое подключение потока (новая станция, переподключение после паузы или прерывания) создаётся новый плеер через `createAudioPlayer`, а не `replace` на старом: `replace` на играющем живом потоке на 1–3 секунды занимает поток JS, и перелёт глобуса замирал. Заменённый плеер глушится (`muted`, не `pause()`: тот через 100 мс выключает аудиосессию, пока новый плеер ещё буферизуется, и в фоне приложение уснуло бы) и освобождается через `release()`, когда глобус не занят перелётом (`flightBusyMs`). Поэтому `player` из контекста меняется, подписки на него должны зависеть от него в эффектах; состояние читается из событий `playbackStatusUpdate` текущего плеера, а не через `useAudioPlayerStatus`. В dev синхронные вызовы плеера замеряются (`timed` из `src/lib/audio-timing.ts`, строки `[audio-timing]` в логе Metro). `play(station, queue)` принимает список, из которого выбрана станция (город, страна, избранное, результаты поиска): по нему работают «вперёд/назад» в панели. Экран блокировки и CarPlay: `setActiveForLockScreen` с `isLiveStream`, заголовок — станция, подзаголовок — «Исполнитель — Трек» или город и страна, обложка — иконка с сайта. Прерывания (звонок, наушники, пауза с экрана блокировки) expo-audio обрабатывает нативно, но возобновляет простым `play()` на старом соединении, которое у живого потока уже мертво, поэтому провайдер отличает прерывание от паузы пользователя (`intentRef`) и при выходе из прерывания переподключает поток (`replace` + `play`). Команды «следующий/предыдущий» с руля, наушников и CarPlay в штатном expo-audio 57 до JS не доходят, их добавляет патч (см. правило 2): провайдер слушает `player.addListener("remoteCommand", …)` и зовёт `next()`/`previous()`.
- Данные станций — статичный `src/data/stations.json` (около 340 городов, ~6,7 тыс. станций, ~2,5 МБ без отступов), сгенерированный скриптом `scripts/generate-stations.mjs` из открытой базы Radio Browser (https://api.radio-browser.info). Список городов с координатами и регионами — `scripts/cities.mjs` (по ним берётся до 40 станций из API; поисковые термины города могут быть названием провинции или штата, тогда все станции региона уходят в его столицу: так устроены Китай, где Radio Browser хранит провинцию в почтовой романизации вроде Kiangsu, и Индия; у островных стран с одним городом на глобусе стоит `wholeCountry: true`, и город получает все станции страны), закреплённые вручную станции (по UUID, с возможной заменой адреса потока) — `scripts/extra-stations.mjs`. Руками JSON не править: меняй города или фильтры и перегенерируй командой `npm run generate-stations` (20 минут при первом запуске; результаты по городам кэшируются в `scripts/.cache/`, флаг `--fresh` качает заново). Общие помощники скриптов (выбор сервера, фильтр играбельных станций, приведение к `Station`) — `scripts/station-utils.mjs`; там же чёрный список названий (станции «0R…» и всё со словом «charts» не берём, их потоки не открываются) и список исключённых стран `EXCLUDED_COUNTRIES` (сейчас Украина, `UA`: её городов нет в `cities.mjs`, кода нет в `generate-countries`, а станции с таким `countrycode` отбрасываются везде, включая `capitals.ts`); оба фильтра применяются и к кэшу, перекачивать ничего не нужно. У каждой станции есть `countryCode`.
- Раскладка по городам для стран с полным списком (см. следующий пункт; поэтому сначала `npm run generate-countries`, потом `npm run generate-stations`). У Radio Browser нет поля «город»: координаты есть примерно у четверти станций, поле `state` заполнено как попало. `scripts/city-matching.mjs` относит станцию к городу из `cities.mjs`, если она в 30 км от него или `state`/название содержат его поисковый термин; остальные станции с координатами группируются по самому крупному городу GeoNames в 25 км (пригороды уходят к центру), а станции с `state`, равным названию города GeoNames, — по нему (кроме названий штатов США). Такая группа становится новым городом на глобусе, если в ней не меньше 5 станций от не меньше чем 5 разных вещателей (иначе сеть вроде 0nradio или SomaFM с одной точкой на сотню потоков стала бы городом); группа рядом с городом из `cities.mjs` вливается в него. Справочник GeoNames (`cities15000`, CC BY 4.0) и английские с русскими названиями из его пострановых файлов alternatenames качает `scripts/geonames.mjs` в `scripts/.cache/geonames/` (архивы не хранятся, только выжимка). Поправки к английским названиям новых городов — `ENGLISH_NAME_OVERRIDES` в `generate-stations.mjs` по id города. Новые города идут после городов своей части света по убыванию числа станций; две трети страновых станций не имеют ни координат, ни узнаваемого города и остаются только в списке страны.
- Полные списки станций по странам (вся Европа, Россия, Казахстан, Индия, Китай, Новая Зеландия, США; остальные страны только городами) — `src/data/country-stations/<код>.json` плюс сгенерированный индекс `index.ts`, команда `npm run generate-countries` (несколько минут, кэш в `scripts/.cache/countries/`). Файлы страны подключаются ленивым `require` при первом обращении (`src/data/countries.ts`), поэтому старт приложения они не замедляют и `tsc` их не разбирает; суммарно ~8 МБ в бандле. Экраны: список стран `cities/countries`, станции страны `cities/country/[code]`, ссылка из экрана города; поиск подключает страновые списки после их разбора (`loadAllCountryStations`). Станции без города попадают в избранное снимком (`favorite-station-snapshots.v1`), в плеере и треках показывается страна. Вся база Radio Browser (~62 тыс.) в JSON не влезает; для неё нужен SQLite или онлайн-запрос к API.

## Правила

1. **Expo-библиотеки приоритетнее сторонних.** Если задачу решает модуль из экосистемы Expo (`expo-audio`, `expo-image`, `expo-haptics` и т. д.), используй его, а не аналог из npm.
2. **Только то, что работает в Expo Go.** Приложение тестируется в Expo Go, поэтому нельзя добавлять библиотеки с нативным кодом, которого нет в Expo Go. Перед добавлением зависимости проверь, что она входит в состав Expo Go для SDK 58. Единственное исключение — патч `patches/expo-audio+58.0.12.patch` (применяется `patch-package` в `postinstall`). В expo-audio 58 кнопки «следующий/предыдущий» на экране блокировки есть штатно (`showNextTrack`/`showPreviousTrack` в `setActiveForLockScreen`), но `MediaController` включает их только для `Playable` с `supportsNextTrack`, то есть для плейлистов; одиночный `AudioPlayer` их не поддерживает. Патч добавляет в `AudioPlayer.swift` `supportsNextTrack`/`supportsPreviousTrack` = true и `nextTrack()`/`previousTrack()`, которые шлют плееру событие `remoteCommand` с `{ command: "next" | "previous" }`, плюс тип события в `AudioModule.types`. Работает только в сборках EAS; в Expo Go событие не приходит, а код должен это переживать молча. После обновления `expo-audio` патч нужно переснять: внести те же правки в `node_modules/expo-audio` и выполнить `npx patch-package expo-audio`.
3. **Устанавливай зависимости через `npx expo install <package>`**, а не `npm install` — так подбирается версия, совместимая с SDK.
4. **Не доверяй памяти про Expo API.** Перед использованием любого Expo/React Native API сверяйся с документацией версии SDK: `https://docs.expo.dev/versions/v57.0.0/`.
5. **Папки `ios/` и `android/` не создавать и не править вручную** — нативная конфигурация только через `app.json` и config-плагины.
6. **Перед завершением задачи** запускай `npx expo lint` и `npx tsc --noEmit`; оба должны проходить без ошибок.
7. **После добавления нового файла-экрана в `src/app/`** выполни `npx expo customize tsconfig.json`: это перегенерирует типизированные маршруты в `.expo/types/router.d.ts`, иначе `tsc` не узнает новый путь (`expo start` делает то же самое, но запускать dev-сервер ради этого не нужно).

## Локализация

- 28 языков интерфейса, по умолчанию английский. Список и порядок показа — `src/i18n/languages.json` (его же читает скрипт названий стран).
- Словари — `src/i18n/translations/<код>.ts`. Английский `en.ts` задаёт набор ключей; остальные типизированы как `Dictionary`, поэтому пропущенный ключ ловит `tsc`. `es-419` и `pt-BR` наследуют `es` и `pt` и переопределяют отличия.
- В компонентах строки брать только через `const { t, language } = useI18n()` из `@/i18n`. Никаких строк интерфейса в коде. Подстановки в виде `{name}`. Множественные формы не используются: числа выводятся как «Станций: 15», чтобы не зависеть от правил склонения 28 языков.
- Новая строка = ключ в `en.ts` + перевод во все словари.
- Названия городов есть только на английском и русском (`city.name.en/ru`, хелпер `cityName`), остальные языки показывают английское. Названия стран на всех языках — `src/data/country-names.json`, генерируется `scripts/generate-country-names.mjs` из Unicode CLDR (в Hermes нет `Intl.DisplayNames`). Регионы — ключи `region.*`.
- Раскладка справа налево для иврита и арабского не включена: текст отображается корректно, но расположение элементов остаётся как в остальных языках.

## Фон и ресурсы (важно для iOS)

iOS завершает фоновое приложение, если оно около минуты держит высокую нагрузку. Поэтому:

- Никаких постоянных циклов `requestAnimationFrame`. В React Native это таймер на 1 мс: на экране он идёт по кадрам дисплея, а в фоне срабатывает до тысячи раз в секунду. Кадр запрашивать только по изменению (см. `requestFrame`/`markDirty` в `src/components/earth-gl.tsx`) и только пока приложение активно.
- Бесконечный HTTP-поток закрывать только через `AbortController.abort()`. `reader.cancel()` в `expo/fetch` на iOS соединение не рвёт, а лишь перестаёт отдавать данные в JS (`src/lib/icy.ts` делает abort в `finally`).
- Сэмплирование звука (`setAudioSamplingEnabled`) включать только пока оно нужно на экране и выключать в cleanup. Штатный `useAudioSampleListener` его не выключает, вместо него `src/hooks/use-dance-energy.ts`.
- Всё, что работает только ради экрана (анализ звука для бобра), останавливать в фоне через `useAppActive()` из `src/hooks/use-app-active.ts`. Опрос названия трека в фоне продолжается, потому что его показывают экран блокировки и CarPlay, но реже (30 с вместо 15), и каждое соединение обрывается через abort.
